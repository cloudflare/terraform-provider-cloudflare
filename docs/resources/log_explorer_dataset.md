# cloudflare_log_explorer_dataset (Resource)

Accepted Permissions

- `Logs Read`
- `Logs Write`

## Example Usage

```terraform
resource "cloudflare_log_explorer_dataset" "example_log_explorer_dataset" {
  dataset               = "http_requests"
  zone_id               = "zone_id"
  filter_attack_traffic = false
  fields = [
    {
      enabled = true
      name    = "edgeendtimestamp"
    },
    {
      enabled = true
      name    = "clientip"
    }
  ]
}
```

## Scope

Configure exactly one of `account_id` or `zone_id`.

## Creation and deletion

The API applies its defaults when `enabled` or `deletion_protection` is omitted.
If a configured value differs from the creation response, the provider applies
it with an update that preserves the selected fields and filter.
Set `deletion_protection = false` and apply the change before deleting the dataset.
The same steps are required before replacing the resource.

## Field selection

When `fields` is omitted, the API selects all available fields. Removing a
configured selection restores that behavior. Imported resources start with
unmanaged fields; configure `fields` to manage a selection.

Names are matched without regard to case. The provider keeps the configured
names and order in state and reads enabled values from the API. Duplicate names
are not allowed, even with different letter case. Each explicit selection must
include the dataset's required timestamp field.

## Schema

### Required

- `dataset` (String) Dataset type name to create (e.g. `http_requests`).

### Optional

- `account_id` (String) The Account ID to use for this endpoint. Mutually exclusive with the Zone ID.
- `deletion_protection` (Boolean) Set to `false` to allow deletion of this dataset.
- `enabled` (Boolean) Whether to enable or disable log ingest for this dataset.
- `fields` (Attributes List) Controls which fields the API ingests. Defaults to all available
fields when absent.
Each dataset requires its own timestamp field to remain enabled (the
field name varies per dataset type); omitting it from an explicit
selection is rejected by the API. (see [below for nested schema](#nestedatt--fields))
- `filter` (String) Optional Logpush filter predicate to restrict which events are ingested.
Omitting this attribute means no filter. An empty string also means no filter.
Removing a configured filter sends an empty string to clear it in the API.
The provider stores missing or null API filters as empty strings in state.
See [Logpush filters](https://developers.cloudflare.com/logs/reference/filters/)
for syntax and examples.
- `filter_attack_traffic` (Boolean) Whether to filter attack traffic from the Logpush job. The API defaults to true on creation for http_requests, firewall_events, and network_analytics_logs. If omitted on update, the existing setting is kept. The API omits this setting for datasets that do not support it.
- `zone_id` (String) The Zone ID to use for this endpoint. Mutually exclusive with the Account ID.

### Read-Only

- `created_at` (String) RFC3339 timestamp recording when the API created this dataset.
- `dataset_id` (String) Unique dataset ID.
- `id` (String) Unique dataset ID.
- `object_id` (String) Public ID of the account or zone that owns this dataset.
- `object_type` (String) Whether this dataset belongs to an account or a zone.
Available values: "account", "zone".
- `updated_at` (String) RFC3339 timestamp recording when the API last updated this dataset.
